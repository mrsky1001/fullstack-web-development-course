# Глава 1. Что такое база данных и зачем она нужна

## ✦ Задание

Понять, что такое реляционная база данных, из каких частей она состоит
и как связана с сервером и клиентом.

## ⌬ Теория

### База данных — хранилище информации

> **Аналогия:** База данных — это **библиотека**. В библиотеке книги
> разложены по полкам (таблицам), у каждой книги есть номер (id),
> название, автор и т.д. Библиотекарь (СУБД) умеет быстро найти
> любую книгу по вашему запросу.

### Реляционная база данных

**Реляционная** (от слова relation — связь) — это база, в которой данные
хранятся в **таблицах**, а таблицы **связаны** между собой.

```
Таблица users             Таблица orders          Таблица products
┌────┬─────────┐         ┌────┬─────┬─────┐     ┌────┬──────────────┐
│ id │ login   │         │ id │user │prod │     │ id │ name         │
├────┼─────────┤    ┌──> ├────┼─────┼─────┤ <──┐├────┼──────────────┤
│  1 │ admin   │───>│    │  1 │  1  │  3  │    ││  1 │ Intel i7     │
│  2 │ ivanov  │───>│    │  2 │  2  │  1  │    ││  2 │ AMD Ryzen 7  │
└────┴─────────┘    │    └────┴─────┴─────┘    │└────┴──────────────┘
                    │         ↑          ↑      │
                    └─────────┘          └──────┘
                   user_id → users.id   product_id → products.id
```

### Что такое MySQL?

**MySQL** — это программа (СУБД — система управления базами данных),
которая хранит данные на жёстком диске и отвечает на SQL-запросы.

Другие СУБД: PostgreSQL, SQLite, MS SQL Server, Oracle.
Мы используем MySQL, потому что она бесплатная и широко распространена.

### Что такое SQL?

**SQL** (Structured Query Language) — язык запросов к базе данных.
С помощью SQL мы:
- **Создаём** таблицы (`CREATE TABLE`)
- **Добавляем** данные (`INSERT INTO`)
- **Читаем** данные (`SELECT`)
- **Обновляем** данные (`UPDATE`)
- **Удаляем** данные (`DELETE`)

### MySQL Workbench

MySQL Workbench — это **графическая программа** для работы с MySQL.
В ней можно:
- Писать и выполнять SQL-запросы
- Видеть таблицы и данные визуально
- Создавать и экспортировать ER-диаграммы

### Где в проекте используется БД?

```
Браузер          Сервер (Node.js)        База данных (MySQL)
─────────       ─────────────────       ────────────────────
Пользователь    server.js               techparts
нажимает        ↓ routes → controllers   ├── users
«В корзину»     ↓ db.query(SQL)          ├── products
                ↓ ← результат            └── orders
← JSON ←       res.json(data)
```

# Глава 2. Установка и настройка MySQL

## ✦ Задание

Установить MySQL Server и MySQL Workbench, подключиться к серверу и убедиться,
что всё работает.

## ⌬ Теория

### Два компонента MySQL

| Компонент | Что делает | Аналогия |
|-----------|-----------|----------|
| **MySQL Server** | Хранит данные, выполняет SQL-запросы | Склад с товарами |
| **MySQL Workbench** | Графический интерфейс для работы | Рация для общения со складом |

MySQL Server работает **как служба** в фоне. Вы его не видите, но он запущен
и ждёт запросов. MySQL Workbench — это окно, через которое вы отправляете
запросы на этот сервер.

## ⚙ Реализация

### Шаг 1: Скачайте MySQL Installer

| | |
|---|---|
| **Сайт** | https://dev.mysql.com/downloads/installer/ |
| **Файл** | `mysql-installer-community-X.X.X.msi` |
| **Выберите** | Full (полная установка) |

### Шаг 2: Установка

1. Запустите установщик
2. Выберите **Developer Default** (включает Server + Workbench)
3. Нажмите **Next → Execute** (установка пакетов)
4. При настройке MySQL Server:
   - **Port:** `3306` (по умолчанию)
   - **Root password:** придумайте пароль (например, `admin`)
   - Запомните этот пароль — он понадобится для `config/db.js`

### Шаг 3: Проверка подключения в Workbench

1. Откройте **MySQL Workbench**
2. На главном экране — блок **MySQL Connections**
3. Кликните на **Local instance MySQL80**
4. Введите пароль, заданный при установке
5. Если открылось окно с редактором SQL — **всё работает!**

```
MySQL Workbench:
┌─────────────────────────────────────────────┐
│  MySQL Connections                          │
│  ┌──────────────────────────────┐           │
│  │ ▪ Local instance MySQL80   │ ← кликни  │
│  │    127.0.0.1:3306            │           │
│  │    root                      │           │
│  └──────────────────────────────┘           │
└─────────────────────────────────────────────┘
```

### Шаг 4: Проверка через командную строку

```bash
mysql -u root -p
```

Введите пароль. Если появилось `mysql>` — сервер работает.

### Устранение неполадок

| Проблема | Решение |
|----------|---------|
| «Can't connect to MySQL server» | MySQL Server не запущен. Откройте «Службы» (services.msc), найдите MySQL80, нажмите «Запустить» |
| «Access denied for user 'root'» | Неверный пароль. Переустановите MySQL или сбросьте пароль |
| Порт 3306 занят | Другая программа занимает порт. В настройках поменяйте на 3307 |

# Глава 3. Создание базы данных и кодировка

## ✦ Задание

Создать базу данных `techparts` с кодировкой `utf8mb4` для поддержки
кириллицы и спецсимволов. *(Критерий №21: 1 балл)*

## ⌬ Теория

### Что такое кодировка?

> **Аналогия:** Кодировка — это **алфавит**, которым записаны данные.
> Если использовать неправильный алфавит, вместо «Привет» вы увидите «ПрÐ²ÐµÑ‚».

| Кодировка | Поддержка | Пример |
|-----------|-----------|--------|
| `latin1` | Только латиница | Hello ✔, Привет ✖ |
| `utf8` | Кириллица + основные символы | Привет ✔, ☺ ✖ |
| `utf8mb4` | Кириллица + эмоджи + все символы | Привет ✔, ☺ ✔ |

Мы используем **`utf8mb4`** — это самая полная кодировка.

### `COLLATE` — правила сравнения

`COLLATE utf8mb4_unicode_ci` определяет, как MySQL сравнивает строки:
- `ci` = Case Insensitive → `'Admin' = 'admin'` (регистр не важен)

### `CREATE DATABASE`

```sql
CREATE DATABASE имя_базы
  CHARACTER SET кодировка
  COLLATE правила_сравнения;
```

### `IF NOT EXISTS`

Если база уже существует, MySQL выдаст ошибку. Чтобы избежать этого:
```sql
CREATE DATABASE IF NOT EXISTS techparts ...
```
`IF NOT EXISTS` = «Создай, только если ещё не существует».

## ⧉ Примеры

### Создать и использовать базу

```sql
-- Создаём базу данных
CREATE DATABASE IF NOT EXISTS my_shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Переключаемся на неё (все дальнейшие команды — внутри этой БД)
USE my_shop;
```

### Показать все базы на сервере

```sql
SHOW DATABASES;
```

Результат:
```
+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| techparts          |   ← наша база
+--------------------+
```

## ⚙ Реализация

### Шаг 1: Откройте MySQL Workbench

1. Подключитесь к серверу (Local instance)
2. Откройте новую вкладку SQL: **File → New Query Tab** (или Ctrl+T)

### Шаг 2: Введите и выполните SQL

```sql
-- ============================================================
-- TechParts — Создание базы данных
-- Критерий №21: 1 балл — БД с правильным именем и кодировкой
-- ============================================================

-- Создаём базу данных «techparts» с кодировкой utf8mb4
-- CHARACTER SET utf8mb4 — для поддержки кириллицы
-- COLLATE utf8mb4_unicode_ci — регистронезависимое сравнение
CREATE DATABASE IF NOT EXISTS techparts
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Переключаемся на созданную базу
-- Все последующие CREATE TABLE будут в этой базе
USE techparts;
```

### Шаг 3: Выполните запрос

Нажмите **► Execute** (значок молнии) или **Ctrl+Shift+Enter**.

В панели **Output** внизу должно появиться:
```
1 row(s) affected
```

### Шаг 4: Проверьте

```sql
SHOW DATABASES;
```

В списке должна быть `techparts`.

> **✖ Частые ошибки:**
> - Имя базы написано с заглавной буквы `TechParts` → в Linux это создаст
>   **другую** базу. Используйте строчные: `techparts`
> - Забыли `USE techparts;` → таблицы создадутся в другой базе

# Глава 4. Таблица `users` — пользователи

## ✦ Задание

Создать таблицу `users` для хранения данных зарегистрированных пользователей:
логин, хеш пароля, ФИО, email, телефон. *(Критерий №21: 5 баллов)*

## ⌬ Теория

### Структура команды `CREATE TABLE`

```sql
CREATE TABLE имя_таблицы (
  имя_столбца  ТИП_ДАННЫХ  ОГРАНИЧЕНИЯ,
  имя_столбца  ТИП_ДАННЫХ  ОГРАНИЧЕНИЯ,
  ...
);
```

### Типы данных SQL

| Тип | Описание | Пример значения | Когда использовать |
|-----|----------|----------------|-------------------|
| `INT` | Целое число | `1`, `42`, `1000` | id, количество |
| `VARCHAR(N)` | Строка до N символов | `'admin'`, `'Иванов'` | Логин, имя, email |
| `TEXT` | Длинный текст (до 65 КБ) | `'Описание товара...'` | Описание, комментарий |
| `DECIMAL(M,D)` | Точное десятичное число | `38990.00` | Цена (M — всего цифр, D — после точки) |
| `DATE` | Дата (ГГГГ-ММ-ДД) | `'2024-12-30'` | Дата доставки |
| `DATETIME` | Дата + время | `'2024-12-30 14:30:00'` | Дата регистрации |

### Ограничения (constraints)

| Ограничение | Что делает | Аналогия |
|------------|-----------|----------|
| `PRIMARY KEY` | Уникальный идентификатор строки | Номер паспорта — у каждого свой |
| `AUTO_INCREMENT` | Номер увеличивается автоматически (1, 2, 3...) | Талончик в очереди |
| `NOT NULL` | Поле обязательно для заполнения | «Без имени не обслуживаем» |
| `UNIQUE` | Значение не может повторяться | «Два человека с одним паспортом — ошибка» |
| `DEFAULT значение` | Если не указано — подставить значение | «По умолчанию — бесплатная доставка» |

### `AUTO_INCREMENT` — автоматический счётчик

```
INSERT → id = 1
INSERT → id = 2   ← не нужно указывать id — MySQL сам увеличивает
INSERT → id = 3
```

### Зачем `VARCHAR(255)` для пароля?

Пароль в базе хранится **не в открытом виде**, а как **хеш** (зашифрованная строка).
Хеш bcryptjs всегда имеет длину ~60 символов: `$2a$10$xK8j...`.
Мы указываем `VARCHAR(255)` с запасом.

## ⧉ Примеры

### Минимальная таблица

```sql
CREATE TABLE students (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(100) NOT NULL
);
```

### Вставка данных

```sql
INSERT INTO students (name) VALUES ('Иванов Иван');
-- id автоматически станет 1
```

### Проверка содержимого

```sql
SELECT * FROM students;
```
Результат:
```
+----+─────────────+
| id | name        |
+----+─────────────+
|  1 | Иванов Иван |
+----+─────────────+
```

## ⚙ Реализация

### Полный SQL для таблицы `users`

```sql
-- ============================================================
-- Таблица users — информация о зарегистрированных пользователях
-- Критерий №21: 5 баллов за корректную таблицу users
-- ============================================================
CREATE TABLE IF NOT EXISTS users (

  -- Первичный ключ с автоинкрементом
  -- Каждый новый пользователь получает уникальный номер: 1, 2, 3...
  id         INT            PRIMARY KEY AUTO_INCREMENT,

  -- Логин — уникальный и обязательный
  -- VARCHAR(50) — до 50 символов
  -- UNIQUE — два пользователя с одинаковым логином невозможны
  login      VARCHAR(50)    NOT NULL UNIQUE,

  -- Хешированный пароль (bcryptjs)
  -- VARCHAR(255) — хеш bcrypt занимает ~60 символов, 255 с запасом
  -- Хранить пароли в открытом виде ЗАПРЕЩЕНО!
  password   VARCHAR(255)   NOT NULL,

  -- ФИО пользователя
  fullname   VARCHAR(150)   NOT NULL,

  -- Email пользователя
  email      VARCHAR(100)   NOT NULL,

  -- Телефон в формате +7 (XXX) XXX-XX-XX
  phone      VARCHAR(20)    NOT NULL,

  -- Дата регистрации — заполняется автоматически
  -- CURRENT_TIMESTAMP = текущая дата и время при вставке записи
  created_at DATETIME       DEFAULT CURRENT_TIMESTAMP
);
```

### Разбор каждого поля

| Поле | Тип | Ограничения | Зачем |
|------|-----|-------------|-------|
| `id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный ID, растёт автоматически |
| `login` | VARCHAR(50) | NOT NULL, UNIQUE | Логин должен быть уникальным |
| `password` | VARCHAR(255) | NOT NULL | Хеш пароля (никогда не хранить открытый!) |
| `fullname` | VARCHAR(150) | NOT NULL | ФИО пользователя |
| `email` | VARCHAR(100) | NOT NULL | Контактный email |
| `phone` | VARCHAR(20) | NOT NULL | Номер телефона |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | Дата регистрации (автоматически) |

> **✖ Частые ошибки:**
> - Забыли `UNIQUE` у `login` → два пользователя с одним логином — данные испортятся
> - Указали `VARCHAR(20)` для пароля → хеш bcrypt не поместится (нужно минимум 60)
> - Забыли `NOT NULL` → пользователь может зарегистрироваться без email

# Глава 5. Таблица `products` — товары

## ✦ Задание

Создать таблицу `products` для хранения каталога комплектующих:
название, описание, цена, категория, изображение.
*(Критерий №21: 5 баллов)*

## ⌬ Теория

### `DECIMAL(10,2)` — точное хранение цены

> **Аналогия:** Тип `FLOAT` — это весы на рынке: могут показать 38990.000.
> Тип `DECIMAL` — это кассовый аппарат: всегда ровно 38990.00.

```
DECIMAL(10,2):
  10 — максимум 10 цифр всего
   2 — из них 2 после запятой

Примеры:
  38990.00   ✔ (7 цифр, 2 после точки)
  99999999.99 ✔ (10 цифр, 2 после точки)
  1000000.00 ✖ (11 цифр — не поместится)
```

Для денег **всегда** используйте `DECIMAL`, не `FLOAT` и не `DOUBLE`!

### `TEXT` vs `VARCHAR`

| Тип | Максимум | Когда использовать |
|-----|---------|-------------------|
| `VARCHAR(200)` | 200 символов | Короткие строки: название, email |
| `TEXT` | 65 535 символов | Длинные тексты: описание товара, комментарии |

### `DEFAULT` — значение по умолчанию

```sql
image VARCHAR(255) DEFAULT 'images/default.jpg'
```
Если при вставке не указать `image`, MySQL подставит `'images/default.jpg'`.

## ⚙ Реализация

### Полный SQL для таблицы `products`

```sql
-- ============================================================
-- Таблица products — информация о доступных комплектующих
-- Критерий №21: 5 баллов за корректную таблицу products
-- ============================================================
CREATE TABLE IF NOT EXISTS products (

  -- Первичный ключ с автоинкрементом
  id          INT            PRIMARY KEY AUTO_INCREMENT,

  -- Название товара (например: «Intel Core i7-14700K»)
  -- VARCHAR(200) — до 200 символов
  name        VARCHAR(200)   NOT NULL,

  -- Описание товара (может быть длинным)
  -- TEXT — до 65 535 символов
  description TEXT           NOT NULL,

  -- Цена в рублях
  -- DECIMAL(10,2) — до 10 цифр, 2 после точки
  -- Например: 38990.00, 72990.00
  price       DECIMAL(10,2)  NOT NULL,

  -- Категория товара (текстовое поле)
  -- Например: «Процессоры», «Видеокарты», «Мониторы»
  category    VARCHAR(100)   NOT NULL,

  -- Путь к изображению (относительный)
  -- DEFAULT — если не указано, подставится дефолтная картинка
  image       VARCHAR(255)   DEFAULT 'images/default.jpg',

  -- Дата добавления товара (автоматически)
  created_at  DATETIME       DEFAULT CURRENT_TIMESTAMP
);
```

### Разбор каждого поля

| Поле | Тип | Зачем |
|------|-----|-------|
| `id` | INT AUTO_INCREMENT | Уникальный номер товара |
| `name` | VARCHAR(200) | Название: «NVIDIA GeForce RTX 4070 Ti» |
| `description` | TEXT | Описание может быть длинным |
| `price` | DECIMAL(10,2) | Точная цена в рублях |
| `category` | VARCHAR(100) | Группировка: «Процессоры», «Видеокарты» |
| `image` | VARCHAR(255) | Путь к файлу изображения |
| `created_at` | DATETIME | Когда товар добавлен |

# Глава 6. Таблица `orders` — заказы (связующая таблица)

## ✦ Задание

Создать таблицу `orders`, которая связывает пользователей с товарами
через внешние ключи. *(Критерий №21: 5 баллов)*

## ⌬ Теория

### Внешний ключ (FOREIGN KEY)

> **Аналогия:** Внешний ключ — это **ссылка на другую таблицу**. Как в
> библиотеке: в формуляре читателя написано «Взял книгу №42». Номер 42
> ссылается на запись в каталоге книг.

```sql
FOREIGN KEY (user_id) REFERENCES users(id)
```

Что это значит:
- Поле `user_id` в таблице `orders` **ссылается** на поле `id` в таблице `users`
- Нельзя создать заказ с `user_id = 999`, если пользователя с `id = 999` нет
- MySQL **сам** проверит, существует ли такой пользователь

### Связь «многие-ко-многим»

Таблица `orders` — это **связующая** (промежуточная) таблица:

```
users (1) ──< orders >── (1) products
  Один пользователь          Один товар
  может иметь                может быть в
  МНОГО заказов              МНОГИХ заказах
```

### `ON DELETE CASCADE`

```sql
FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
```

**CASCADE** (каскад) означает: если удалить пользователя из `users`,
все его заказы из `orders` удалятся **автоматически**.

| Действие | Что произойдёт |
|----------|---------------|
| `DELETE FROM users WHERE id = 5` | Все заказы пользователя №5 удалятся из `orders` |
| Без CASCADE | MySQL выдаст ошибку: «Нельзя удалить — есть связанные записи» |

### Схема связей (ER)

```
┌──────────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│       users          │     │       orders          │     │      products        │
├──────────────────────┤     ├──────────────────────┤     ├──────────────────────┤
│ id (PK)           ◄──┼──── │ user_id (FK)          │     │ id (PK)           ◄──┤
│ login                │     │ product_id (FK)    ────┼────►│ name                 │
│ password             │     │ delivery_date       │     │ description          │
│ fullname             │     │ quantity            │     │ price                │
│ email                │     │ total_price         │     │ category             │
│ phone                │     │ comment             │     │ image                │
│ created_at           │     │ created_at          │     │ created_at           │
└──────────────────────┘     └──────────────────────┘     └──────────────────────┘

PK = Primary Key (первичный ключ)
FK = Foreign Key (внешний ключ)
◄── = ссылка (REFERENCES)
```

## ⧉ Примеры

### Таблица со внешним ключом (минимальный пример)

```sql
-- Таблица-родитель
CREATE TABLE authors (
  id   INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100) NOT NULL
);

-- Таблица-потомок со ссылкой
CREATE TABLE books (
  id        INT PRIMARY KEY AUTO_INCREMENT,
  title     VARCHAR(200) NOT NULL,
  author_id INT NOT NULL,
  FOREIGN KEY (author_id) REFERENCES authors(id)
);
```

### Что произойдёт при неправильной ссылке

```sql
INSERT INTO books (title, author_id) VALUES ('Книга', 999);
-- ОШИБКА: Cannot add or update a child row:
-- a foreign key constraint fails
-- Автора с id = 999 не существует!
```

## ⚙ Реализация

### Полный SQL для таблицы `orders`

```sql
-- ============================================================
-- Таблица orders — связывает пользователей с заказанными товарами
-- Связующая таблица в архитектуре базы данных
-- Критерий №21: 5 баллов за корректную таблицу orders
-- ============================================================
CREATE TABLE IF NOT EXISTS orders (

  -- Первичный ключ с автоинкрементом
  id            INT            PRIMARY KEY AUTO_INCREMENT,

  -- Внешний ключ на таблицу users
  -- Указывает, КАКОЙ пользователь сделал заказ
  user_id       INT            NOT NULL,

  -- Внешний ключ на таблицу products
  -- Указывает, КАКОЙ товар заказан
  product_id    INT            NOT NULL,

  -- Дата доставки (формат DATE: ГГГГ-ММ-ДД)
  delivery_date DATE           NOT NULL,

  -- Количество единиц (от 1 до 10)
  quantity      INT            NOT NULL,

  -- Общая стоимость = цена × количество
  -- DECIMAL(10,2) — точное хранение денег
  total_price   DECIMAL(10,2)  NOT NULL,

  -- Комментарий к заказу (необязательное поле)
  -- DEFAULT NULL — если не указано, будет пустым
  comment       TEXT           DEFAULT NULL,

  -- Дата создания заказа (автоматически)
  created_at    DATETIME       DEFAULT CURRENT_TIMESTAMP,

  -- ============================================================
  -- ВНЕШНИЕ КЛЮЧИ — связи между таблицами
  -- ============================================================

  -- user_id → users.id
  -- ON DELETE CASCADE: если удалить пользователя — его заказы удалятся
  FOREIGN KEY (user_id)    REFERENCES users(id)    ON DELETE CASCADE,

  -- product_id → products.id
  -- ON DELETE CASCADE: если удалить товар — связанные заказы удалятся
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);
```

### Порядок создания таблиц ВАЖЕН!

```
1. users      ← создаётся ПЕРВОЙ (нет зависимостей)
2. products   ← создаётся ВТОРОЙ (нет зависимостей)
3. orders     ← создаётся ПОСЛЕДНЕЙ (зависит от users и products)
```

Если попытаться создать `orders` до `users` — MySQL выдаст ошибку:
```
ERROR: Cannot add foreign key constraint
```

> **✖ Частые ошибки:**
> - Создали `orders` раньше `users` или `products` → ошибка внешнего ключа
> - Забыли `ON DELETE CASCADE` → при удалении пользователя база выдаёт ошибку
> - Тип `user_id` (INT) не совпадает с типом `users.id` (INT) → ключ не создастся.
>   Типы ДОЛЖНЫ совпадать

# Глава 8. Полезные SQL-запросы для проекта

## ✦ Задание

Изучить основные SQL-запросы: SELECT, WHERE, JOIN, INSERT, UPDATE, DELETE.
Эти запросы используются в контроллерах backend.

## ⌬ Теория

### CRUD — четыре операции с данными

| Операция | SQL | Пример из проекта |
|----------|-----|--------------------|
| **C**reate (создать) | `INSERT` | Регистрация пользователя |
| **R**ead (читать) | `SELECT` | Список товаров, мои заказы |

## ⧉ Примеры

### SELECT — чтение данных

```sql
-- Все товары
SELECT * FROM products;

-- Только названия и цены
SELECT name, price FROM products;

-- Товары дешевле 30000
SELECT * FROM products WHERE price < 30000;

-- Товары из категории «Процессоры»
SELECT * FROM products WHERE category = 'Процессоры';

-- Отсортировать по цене (от дешёвых к дорогим)
SELECT * FROM products ORDER BY price ASC;

-- Отсортировать по цене (от дорогих к дешёвым)
SELECT * FROM products ORDER BY price DESC;

-- Поиск по названию (содержит «Intel»)
SELECT * FROM products WHERE name LIKE '%Intel%';

-- Количество товаров
SELECT COUNT(*) AS total FROM products;
```

### INSERT — добавление данных

```sql
-- Добавить нового пользователя
INSERT INTO users (login, password, fullname, email, phone)
VALUES ('ivanov', '$2a$10$hash...', 'Иванов Иван Иванович', 'ivanov@mail.ru', '+7 (999) 111-22-33');
```

### UPDATE — обновление данных

```sql
-- Изменить цену товара с id = 1
UPDATE products SET price = 39990.00 WHERE id = 1;

-- Изменить email пользователя
UPDATE users SET email = 'newemail@mail.ru' WHERE login = 'ivanov';
```

> **! ВАЖНО:** Всегда указывайте `WHERE`! Без `WHERE` обновятся **ВСЕ** строки:
> ```sql
> UPDATE products SET price = 0;  -- ВСЕ товары станут бесплатными!
> ```

### DELETE — удаление данных

```sql
-- Удалить товар с id = 7
DELETE FROM products WHERE id = 7;

-- Удалить все заказы пользователя с id = 1
DELETE FROM orders WHERE user_id = 1;
```

> **! ВАЖНО:** Без `WHERE` удалятся **ВСЕ** записи:
> ```sql
> DELETE FROM products;  -- Все товары удалены!
> ```

### JOIN — объединение таблиц

```sql
-- Получить заказы с названиями товаров

SELECT
  o.id AS order_id,

  p.name AS product,
  o.quantity,
  o.total_price,

JOIN users u ON o.user_id = u.id
JOIN products p ON o.product_id = p.id;
```

```sql
-- TechParts — Создание базы данных и таблиц

);

-- ============================================================

  category    VARCHAR(100)   NOT NULL,
  image       VARCHAR(255)   DEFAULT 'images/default.jpg',
  created_at  DATETIME       DEFAULT CURRENT_TIMESTAMP
);

-- ============================================================
-- ШАГ 4: Таблица orders (связующая)
-- 5 баллов за корректную таблицу orders
```

# Глава 10. ER-диаграмма

## ✦ Задание

Создать и сохранить ER-диаграмму (Entity-Relationship) для базы данных
проекта. *(Критерий №21: 2 балла)*

## ⌬ Теория

### Что такое ER-диаграмма?

> **Аналогия:** ER-диаграмма — это **чертёж** базы данных. Как архитектор
> рисует план дома перед строительством, так и мы рисуем план таблиц
> перед (или после) их создания.

ER-диаграмма показывает:
- **Таблицы** (прямоугольники)
- **Поля** (строки внутри прямоугольников)
- **Связи** (линии между таблицами)
- **Типы связей** (1:1, 1:N, N:M)

### Типы связей

| Связь | Обозначение | Пример |
|-------|------------|--------|
| Один-к-одному (1:1) | ─── | Пользователь → Профиль |
| Один-ко-многим (1:N) | ──< | Пользователь → Много заказов |
| Многие-ко-многим (N:M) | >──< | Через промежуточную таблицу |

В нашем проекте:
- `users` 1──<N `orders` — один пользователь → много заказов
- `products` 1──<N `orders` — один товар → много заказов

## ⚙ Реализация

### Способ 1: Автоматическая генерация в MySQL Workbench

1. Откройте MySQL Workbench
2. Подключитесь к серверу
3. Меню: **Database → Reverse Engineer...**
4. Нажмите **Next** → введите пароль → **Next**
5. Выберите базу `techparts` → **Next** → **Next** → **Execute**
6. Появится ER-диаграмма с таблицами и связями

### Способ 2: Создание вручную (EER Model)

1. Меню: **File → New Model**
2. Дважды кликните **Add Diagram**
3. На панели слева перетащите таблицы на диаграмму
4. Инструментом «1:N Relationship» нарисуйте связи

### Как сохранить диаграмму

1. **Как файл модели:** File → Save Model As → `techparts_erd.mwb`
2. **Как изображение:** File → Export → Export as PNG
3. Сохраните в папку `database/` проекта


# Глава 11. Подключение базы данных к серверу

## ✦ Задание

Настроить файл `config/db.js` в backend для подключения Node.js к MySQL.

## ⌬ Теория

### Модуль `mysql2`

Node.js не умеет «разговаривать» с MySQL сам по себе. Для этого нужен
пакет `mysql2`, который устанавливается через npm:

```bash
npm install mysql2
```

### Пул соединений (Connection Pool)

> **Аналогия:** Без пула — это как один телефон на весь офис: пока
> один разговаривает, остальные ждут. Пул — это **10 телефонов**:
> 10 запросов одновременно.

```javascript
const pool = mysql.createPool({
  host: 'localhost',
  user: 'root',
  password: 'admin',
  database: 'techparts'
});
```

### Промисы (.promise())

```javascript
// БЕЗ промисов (callback — старый стиль):
pool.query('SELECT * FROM users', (err, results) => {
  if (err) throw err;
  console.log(results);
});

// С промисами (async/await — современный стиль):
const [results] = await pool.promise().query('SELECT * FROM users');
console.log(results);
```

## ⚙ Реализация

```javascript
// ============================================================

// Критерий №1: Стек — MySQL (mysql2 с промисами)
// Критерий №21: БД с правильным именем и кодировкой
// ============================================================

const mysql = require('mysql2');

// --- Создаём пул подключений ---
const pool = mysql.createPool({
  host: 'localhost',       // Адрес MySQL-сервера (локальный)
  user: 'root',            // Имя пользователя MySQL
  password: 'admin',       // Пароль (тот, что задали при установке)
  database: 'techparts',   // Имя базы данных (из schema.sql)
  charset: 'utf8mb4'       // Кодировка для кириллицы
});

// --- Экспортируем пул с промисами ---
// .promise() позволяет использовать async/await в контроллерах
module.exports = pool.promise();
```

### Как это используется в контроллерах

```javascript
// В любом контроллере (например, productController.js):
const db = require('../config/db');

exports.getAll = async (req, res) => {
  // db.query возвращает [массив_строк, метаданные]
  // Деструктуризация: берём только массив строк
  const [products] = await db.query('SELECT * FROM products ORDER BY id');
  res.json(products);
};
```

### Проверка подключения

Добавьте временный тест в `server.js` (потом удалите):

```javascript
const db = require('./config/db');

// Тест подключения к БД
db.query('SELECT 1')
  .then(() => console.log('✔ MySQL подключён'))
  .catch(err => console.error('✖ Ошибка MySQL:', err.message));
```

### Частые ошибки подключения

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `ECONNREFUSED` | MySQL-сервер не запущен | Запустите MySQL через «Службы» (services.msc) |
| `Access denied for user 'root'` | Неверный пароль | Проверьте пароль в `db.js` |
| `Unknown database 'techparts'` | База не создана | Выполните `schema.sql` в Workbench |
| `ER_NOT_SUPPORTED_AUTH_MODE` | Старый протокол аутентификации | В MySQL Workbench выполните: `ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'ваш_пароль';` |

### Чек-лист проверки в MySQL Workbench

Выполните каждый запрос и убедитесь, что результат правильный:

#### 1. Проверка базы данных

```sql
SHOW DATABASES;
-- В списке должна быть «techparts»
```

#### 2. Проверка таблиц

```sql
USE techparts;

```

Ожидаемый результат:
```
+---------------------+
| Tables_in_techparts |
+---------------------+
| orders              |
| products            |
| users               |
+---------------------+
3 rows in set
```

#### 3. Структура каждой таблицы

```sql
DESCRIBE users;
DESCRIBE products;
DESCRIBE orders;
```

Пример для `users`:
```
+-----------+--------------+------+-----+-------------------+
| Field     | Type         | Null | Key | Default           |
+-----------+--------------+------+-----+-------------------+
| id        | int          | NO   | PRI | NULL              |
| login     | varchar(50)  | NO   | UNI | NULL              |
| password  | varchar(255) | NO   |     | NULL              |
| fullname  | varchar(150) | NO   |     | NULL              |
| email     | varchar(100) | NO   |     | NULL              |
| phone     | varchar(20)  | NO   |     | NULL              |
| created_at| datetime     | YES  |     | CURRENT_TIMESTAMP |
+-----------+--------------+------+-----+-------------------+
```

#### 4. Проверка данных в products

```sql
SELECT id, name, price, category FROM products;
-- Должно быть 7 товаров
```

#### 5. Проверка внешних ключей

```sql
-- Попробуем вставить заказ с несуществующим пользователем
INSERT INTO orders (user_id, product_id, delivery_date, quantity, total_price)
VALUES (999, 1, '2024-12-30', 1, 38990.00);
-- Ожидается ОШИБКА: Cannot add or update a child row

```

#### 6. Проверка кодировки

```sql
-- Вставляем строку с кириллицей
INSERT INTO users (login, password, fullname, email, phone)
VALUES ('test', 'hash', 'Тестовый Пользователь', 'test@test.ru', '+7 (000) 000-00-00');

SELECT fullname FROM users WHERE login = 'test';
-- Должно быть: «Тестовый Пользователь» (не крокозябры)

-- Удаляем тестовую запись
DELETE FROM users WHERE login = 'test';
```
