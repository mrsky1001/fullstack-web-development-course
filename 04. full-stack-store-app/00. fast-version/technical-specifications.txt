────────────────────────────────────────────────────────────────────────────────
  ТЕХНИЧЕСКОЕ ЗАДАНИЕ
  Разработка интернет-магазина компьютерных комплектующих «TechParts»
  Тема: «Собери ПК своей мечты»
────────────────────────────────────────────────────────────────────────────────


╔══════════════════════════════════════════════════════════════════════════════╗
║  ОПИСАНИЕ ЗАДАНИЯ                                                          ║
╚══════════════════════════════════════════════════════════════════════════════╝

Разработать интернет-магазин компьютерных комплектующих «TechParts» с полноценной
регистрацией, авторизацией и базой данных MySQL. Все данные хранятся в базе
данных, пользователи проходят регистрацию и авторизацию, могут просматривать
каталог комплектующих и оформлять заказы (добавлять товары в корзину).

  ► Время на выполнение: 4 часа


╔══════════════════════════════════════════════════════════════════════════════╗
║  ТЕХНОЛОГИИ                                                                ║
╚══════════════════════════════════════════════════════════════════════════════╝

  • Frontend:  HTML5, CSS3, JavaScript
  • Backend:   Node.js + Express, MySQL (mysql2 с промисами),
               express-session (сессии), bcryptjs (хеширование паролей),
               MVC-архитектура


╔══════════════════════════════════════════════════════════════════════════════╗
║  ОБЩИЕ ТРЕБОВАНИЯ                                                          ║
╚══════════════════════════════════════════════════════════════════════════════╝

  • Использовать семантические теги (header, main, footer, nav, section).
  • Исходные изображения могут быть иного размера — с помощью стилизации
    нужно растянуть их на весь блок без искажения и центрировать.
  • Корректное отображение на экранах с шириной от 1200px.
  • В формах необходимо требовать от пользователя ввести все поля
    (кроме необязательных).
  • Шапка и подвал сайта используются на всех страницах.
  • Подобрать цветовую гамму из 3–5 основных цветов для фона и текста
    (оттенков может быть больше).
  • Современная вёрстка и расположение элементов с помощью flexbox/grid.

┌──────────────────────────────────────────────────────────────────────────────┐
│  1. ГЛАВНАЯ СТРАНИЦА (index.html)                                          │
│     Доступна всем посетителям без необходимости авторизации                 │
└──────────────────────────────────────────────────────────────────────────────┘

ШАПКА (HEADER)
  В верхней части страницы располагается шапка с логотипом, состоящим из
  векторного изображения формата SVG и названия сайта «TechParts», а также
  навигационным меню, которое меняется в зависимости от статуса авторизации:

  ● Для неавторизованных посетителей меню содержит три элемента:
    — ссылку «Главная», ведущую на index.html;
    — ссылку «Каталог», ведущую на catalog.html;
    — кнопку «Войти», ведущую на страницу login.html.

  ● Для авторизованных пользователей меню отображает четыре элемента:
    — ссылку «Главная»;
    — ссылку «Каталог»;
    — ссылку «Корзина», ведущую на cart.html;
    — кнопку «Выйти» для завершения сессии и возврата на главную
      в качестве неавторизованного посетителя.

  Проверка статуса авторизации происходит при загрузке каждой страницы
  через JavaScript-запрос к серверу. На основании ответа JavaScript
  динамически формирует соответствующее навигационное меню.

СЛАЙДЕР
  Далее по центру горизонтали отображается блок со слайдером, содержащим
  четыре изображения одинакового размера — 800×400 пикселей.
  Слайдер работает в автоматическом режиме, сменяя изображения каждые
  три секунды. Под изображениями располагаются индикаторы в виде точек,
  показывающие текущий слайд. Пользователь может управлять слайдером
  вручную с помощью кнопок «Вперёд» и «Назад» в виде стрелок.
  Весь функционал слайдера реализуется на чистом JavaScript
  без использования сторонних библиотек.

СЕКЦИЯ «ПОПУЛЯРНЫЕ ТОВАРЫ»
  Под слайдером размещается секция «Популярные товары», содержащая три
  карточки с краткой информацией о самых востребованных комплектующих.
  Каждая карточка включает:
    — изображение размером 300×200 пикселей;
    — название товара;
    — краткое описание;
    — цену в рублях.
  Внизу секции расположена кнопка «Весь каталог», ведущая на страницу
  каталога.

ПОДВАЛ (FOOTER)
  В нижней части страницы располагается подвал с контактной информацией
  магазина, включающей:
    — email: info@techparts.ru
    — телефон: +7 (800) 555-35-35
    — и другую информацию из приложенных к заданию материалов.


┌──────────────────────────────────────────────────────────────────────────────┐
│  2. СТРАНИЦА РЕГИСТРАЦИИ (register.html)                                   │
│     Доступна всем посетителям без необходимости авторизации                 │
└──────────────────────────────────────────────────────────────────────────────┘

В заголовке страницы размещается текст «Регистрация в TechParts».

Форма регистрации содержит следующие поля:

  1) Логин — только латинские буквы и цифры, минимальная длина 5 символов.
     Валидация логина происходит как на стороне клиента при заполнении формы,
     так и на стороне сервера для проверки уникальности.

  2) Пароль (input type="password") — минимальная длина 8 символов.

  3) Повтор пароля — для подтверждения. Система проверяет совпадение
     обоих введённых значений.

  4) Полное ФИО пользователя — система проверяет, что введено минимум
     три слова, используя кириллические символы и пробелы.

  5) Email — с валидацией корректности формата на наличие символов «@» и «.».

  6) Номер телефона — в формате +7 (XXX) XXX-XX-XX.

  ► У каждого поля формы должно быть краткое описание и плейсхолдер.

  При нажатии кнопки «Зарегистрироваться» данные отправляются на сервер,
  проверяется уникальность логина в базе данных, хешируется пароль
  с использованием bcryptjs и происходит сохранение нового пользователя
  в таблицу users.

  ● Успех: пользователь видит сообщение «Регистрация успешна! Теперь вы
    можете войти.». Словосочетание «можете войти» должно быть ссылкой,
    ведущей на страницу авторизации.

  ● Ошибка: если логин уже занят, рядом с полем отображается
    соответствующее сообщение красным цветом, а само поле выделяется
    красным, пока пользователь не начнёт менять значение.


┌──────────────────────────────────────────────────────────────────────────────┐
│  3. СТРАНИЦА АВТОРИЗАЦИИ (login.html)                                      │
│     Доступна всем посетителям без необходимости авторизации                 │
└──────────────────────────────────────────────────────────────────────────────┘

В заголовке страницы размещается текст «Вход в систему».

Страница содержит форму с полями и подписями к ним: логин и пароль,
а также кнопку «Войти», которая отправляет введённые данные на сервер
для сверки.

  ● Успех: создаётся серверная сессия с использованием express-session,
    в которой сохраняется идентификатор пользователя user_id. Эта сессия
    позволяет системе идентифицировать пользователя при последующих запросах
    без повторного ввода пароля. Пользователь автоматически перенаправляется
    на страницу каталога комплектующих.

  ● Ошибка: под формой появляется сообщение красным цветом с текстом
    «Неверный логин или пароль».

  Под формой присутствует ссылка для незарегистрированных пользователей
  с текстом «Ещё не зарегистрированы? Регистрация», ведущая на страницу
  регистрации.


┌──────────────────────────────────────────────────────────────────────────────┐
│  4. СТРАНИЦА КАТАЛОГА (catalog.html)                                       │
│     Доступна всем посетителям; добавление в корзину — только авторизованным │
└──────────────────────────────────────────────────────────────────────────────┘

В заголовке страницы размещается текст «Каталог комплектующих».

При загрузке страницы выполняется запрос к серверу для получения списка
всех доступных комплектующих из базы данных, после чего динамически
создаются карточки для каждого товара.

Каждая карточка товара содержит:
  — изображение размером 300×200 пикселей;
  — название;
  — описание;
  — цену в рублях;
  — категорию товара (например: процессоры, видеокарты, материнские платы,
    оперативная память);
  — кнопку «В корзину».

При клике на кнопку «В корзину» система проверяет наличие активной сессии:
  ● Неавторизованный пользователь: появляется всплывающее окно
    с текстом «Войдите, чтобы добавить товар в корзину».
  ● Авторизованный пользователь: товар добавляется в корзину
    с передачей идентификатора выбранного товара на сервер.

Над карточками располагается блок с дополнительными функциями:
  1) Текстовое поле для поиска товаров по названию (фильтрация).
  2) Сортировка товаров по цене в порядке возрастания и убывания.


┌──────────────────────────────────────────────────────────────────────────────┐
│  5. СТРАНИЦА ОФОРМЛЕНИЯ ЗАКАЗА (order.html)                                │
│     Доступна исключительно авторизованным пользователям                     │
└──────────────────────────────────────────────────────────────────────────────┘

При попытке открыть эту страницу выполняется проверка наличия активной
сессии через запрос к серверу. Если сессия отсутствует — автоматический
редирект на страницу авторизации.

В заголовке страницы размещается текст «Оформление заказа».

Форма оформления заказа состоит из четырёх полей:

  1) Выпадающий список для выбора товара (select) — список заполняется
     автоматически при загрузке страницы; активным будет тот товар,
     по которому произошёл переход.

  2) Поле с выбором даты доставки — реализуется через input type="date".
     JavaScript проверяет, что выбранная дата не раньше сегодняшнего дня.

  3) Числовое поле для указания количества единиц товара — ввести можно
     только целые числа от 1 до 10.

  4) Текстовое поле для комментария, где пользователь может указать
     дополнительные пожелания к заказу. Поле необязательно для ввода.

Под полями формы отображается надпись с автоматически рассчитанной общей
стоимостью заказа в зависимости от количества единиц:
«Общая стоимость: X руб.».

При нажатии кнопки «Оформить заказ», если все нужные данные введены
корректно, они отправляются на сервер, а в базу данных в таблицу orders
добавляется новая запись со всеми данными из формы, включая привязку
к user_id из сессии и общую стоимость заказа.

  ● Успех: на экране появляется сообщение «Ваш заказ оформлен!
    Номер заказа: #X» (где X — идентификатор созданной записи)
    и кнопка для перехода на страницу «Мои заказы».


┌──────────────────────────────────────────────────────────────────────────────┐
│  6. СТРАНИЦА «МОИ ЗАКАЗЫ» (my-orders.html)                                 │
│     Доступна исключительно авторизованным пользователям                     │
└──────────────────────────────────────────────────────────────────────────────┘

При попытке открыть эту страницу выполняется проверка наличия активной
сессии через запрос к серверу. Если сессия отсутствует — автоматический
редирект на страницу авторизации.

В заголовке страницы размещается текст «Мои заказы».

Для авторизованных пользователей выполняется запрос к серверу для получения
всех заказов текущего пользователя вместе с информацией о заказанных
товарах.

Полученные данные отображаются в виде карточек, аналогичных карточкам
каталога, но каждая карточка содержит:
  — изображение товара размером 300×200 пикселей;
  — название товара;
  — номер заказа в формате «Заказ #X»;
  — дата доставки;
  — количество единиц;
  — общая стоимость заказа.

Если у пользователя нет ни одного заказа, вместо карточек отображается
сообщение: «У вас пока нет заказов. Перейдите в каталог и выберите
комплектующие для вашего ПК!» и кнопка «Перейти в каталог» для быстрого
доступа к catalog.html.

  ТРЕБОВАНИЯ К БАЗЕ ДАННЫХ
════════════════════════════════════════════════════════════════════════════════

База данных создаётся в MySQL с именем techparts и кодировкой с правильным
отображением кириллических символов.

Структура состоит из трёх основных таблиц с установленными связями
через внешние ключи:

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  Таблица users — информация о зарегистрированных пользователях         │
  ├──────────────────────────────────────────────────────────────────────────┤
  │  • Первичный ключ с автоинкрементом                                    │
  │  • Логин (уникальный), ФИО, email и телефон — обязательны              │
  │  • Хешированный пароль                                                 │
  │  • Автоматическая фиксация даты создания записи                       │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  Таблица products — информация о доступных комплектующих               │
  ├──────────────────────────────────────────────────────────────────────────┤
  │  • Первичный ключ с автоинкрементом                                    │
  │  • Цена в формате DECIMAL(10,2)                                        │
  │  • Категория товара (текстовое поле)                                   │
  │  • Минимум 4 записи                                                    │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  Таблица orders — связывает пользователей с заказанными товарами       │
  │  (связующая таблица в архитектуре базы данных)                         │
  ├──────────────────────────────────────────────────────────────────────────┤
  │  • Первичный ключ с автоинкрементом                                    │
  │  • Два внешних ключа с каскадным удалением                             │
  │  • Расчёт общей стоимости                                              │
  │  • Автоматическая фиксация даты создания заказа                       │
  └──────────────────────────────────────────────────────────────────────────┘

Необходимо создать ER-диаграмму всех таблиц и сохранить её как изображение
в формате PNG для включения в финальный архив работы.
